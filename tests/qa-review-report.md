# QA / Security 交叉审查报告

执行时间：2026-08-06（Asia/Shanghai）

## 结论

**已实现开发切片：修改后通过。生产发布：阻断。**

当前活动发现、创建/发布、报名/取消、路书展示和我的报名切片通过自动化门禁。阻断生产发布的原因不是已发现的 P0 代码缺陷，而是 PostgreSQL 真库用例未在本机执行、微信真机/合法域名未验收，以及冻结方案中的活动编辑/取消通知、GPX 导入、内容治理与运营后台尚未交付。

## 已关闭问题

- P0 身份伪造：写接口改为验证 Bearer JWT，忽略客户端自报用户 ID；已有伪造 token 和跨用户取消回归测试。
- P0 报名一致性：内存仓储与 PostgreSQL 适配器均采用原子事务；并发、重复报名、幂等重放和取消只释放一次均有测试。
- P0 隐私：手机号和紧急联系人不进入 API 响应，使用随机 IV 的 AES-256-GCM 加密后存储；密钥缺失时启动失败。
- P0 坐标：服务端保留 WGS84，小程序映射到微信地图前仅转换一次 GCJ-02。
- P1 前后端契约：分页 DTO、两阶段发布、报名请求、登录、完整历史报名聚合和路书轨迹字段已对齐。
- P1 边界：报名在截止时间精确时刻关闭，前后端都有回归测试。
- P1 迁移：事务只由迁移运行器持有，迁移文件不再嵌套 `BEGIN/COMMIT`。
- P1 依赖：`find-my-way` 高危漏洞的安装树已修复；两端生产依赖审计均为 0 漏洞。
- P2 工程入口：根 README 已以正式小程序和 API 为主入口，并明确核心切片与生产发布边界。
- P2 门禁漂移：根 `npm run verify` 已统一调用 `scripts/quality-gate.mjs`，包含扫描器自测和生产依赖审计。

## 未关闭风险

| 等级 | 风险 | 放行条件 |
|---|---|---|
| P1 | 本机无 Docker/PostgreSQL，`postgres.integration.test.ts` 被跳过，尚无本轮真实数据库并发证据 | 在一次性迁移数据库执行 `npm run test:postgres`，保存 20-100 倍容量并发结果 |
